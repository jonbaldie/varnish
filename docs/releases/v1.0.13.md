# v1.0.13

## Fixes

- Preserve graced cached pages when a background refresh receives an origin 5xx. Foreground errors remain uncacheable, and errors do not extend the grace window.
- Invalidate all encoding variants for an authorized PURGE of an exact host and URL. The loopback ACL remains in place. Invalidation uses a ban, which is checked on lookup or by the ban lurker. A rejected ban returns `500 Purge failed`.
- Pass the same listen, VCL, storage, and extra arguments to `/start.sh --check` and startup. Preflight now resolves and binds the listener. Run it in the deployment network on an available listener, not the live instance's port.
- Keep backend configuration checks isolated from live VCL. Startup publishes a generated backend only after validation succeeds. The embedded VCL now uses a relative `backend.vcl` include. Custom `vcl_path` settings must allow that include to resolve.

## Tests

- Share the campaign HTTP client and preserve repeated response headers with case-insensitive lookup.
- Correlate campaign responses with origin request records and scope observations to a checkpoint.

## Known issue

- Each authorized PURGE now adds a ban. Successful unsafe requests already added bans. Outstanding bans can add work to unrelated cache lookups. See [#168](https://github.com/jonbaldie/varnish/issues/168).
