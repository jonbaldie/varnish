# v1.0.13

## Fixes

- Preserve graced cached pages when a background refresh receives an origin 5xx. Foreground errors remain uncacheable, and errors do not extend the grace window.
- Invalidate all encoding variants for an authorized PURGE of an exact host and URL. The loopback ACL remains in place. Invalidation uses a ban and occurs on lookup.
- Pass the same listen, VCL, storage, and extra arguments to `/start.sh --check` and startup. Run preflight in the deployment network and on an available listener.
- Keep backend configuration checks isolated from live VCL. Startup publishes a generated backend only after validation succeeds.

## Tests

- Share the campaign HTTP client and preserve repeated response headers with case-insensitive lookup.
- Correlate campaign responses with origin request records and scope observations to a checkpoint.

## Known issue

- Exact-identity bans can add work to unrelated cache lookups while bans are outstanding. See [#168](https://github.com/jonbaldie/varnish/issues/168).
